# 次アクション整理メモ

## 決まったこと

- 1ターンの粒度は `1学期`
- ゲームの区切りは `卒業`
- バレー部ストーリーは主軸ではなく `任意の寄り道`
- 先にエンディングを作るより、まず `1学期の手触り` を整える


## 現状認識

今すでにある実装は強い。

- 学期進行と身体測定UI
- 成長履歴とグラフ
- かがむ物理と頭上干渉
- NPCの身長差リアクション
- 家、学校、駅などの比較しやすいステージ
- バレー部を含む会話イベント

不足しているのは要素数ではなく、これらを束ねるゲームループ。
いまは「歩いて比較する」「テキストを読む」はできているが、「今学期は何を優先するか」の判断がまだ弱い。


## いまの主眼

最優先は `1学期だけ遊んでも面白い` こと。

卒業までの長い流れより先に、

- その学期にどこで過ごすか迷う
- 行き先によって体験が変わる
- 終わりに成長や余韻が残る

という最小ループを作る。


## パラメータ方針の見直し

### `目立ち度` はそのままだと曖昧

レビューの指摘どおり、単に「上がると何か良さそう」では弱い。
もし使うなら、意味は `外部からの注目の蓄積` に限定した方がよい。

仮の定義:

- 学校や繁華街で人目にさらされると上がる
- 家ではほぼ上がらない
- 高くなると、周囲の反応が「個人の感想」から「噂・話題・特別扱い」に変わる

具体的な使い道:

- クラスで噂になる
- 先生や保健室から特別に気にかけられる
- 繁華街で視線やざわつきが増える
- 卒業時の後日談が「静かに過ごした」か「目立つ存在になった」かで変わる

重要なのは、`注目そのものが報酬` ではなく、`起こるイベントの種類を変えるゲート` として使うこと。

### 最初は `ストレス` を主軸、`注目` は補助でもよい

最初の1本目では、無理に2軸とも強く使わなくてもよい。

最小構成案:

- 主軸: `ストレス`
- 補助: `注目`

これなら、まずは「しんどい場所に行くか、落ち着ける場所に行くか」という判断が作れる。


## 学校に行く意味

バレー部を主軸にしないなら、学校の意味は別に用意する必要がある。

代替案として有力なのは `学校 = 社会との摩擦が最も濃い場所` と定義すること。

学校で起きることの候補:

- 座席、机、黒板、廊下などとのサイズ差
- 先生からの視線や配慮
- 保健室での測定や経過観察
- 友人との会話や噂
- 行事の並び順、写真、整列などでの違和感

この構造なら、バレー部はその中の一ルートとして自然に置ける。


## エリア方針

`家 / 学校 / 繁華街` という役割分担はまだ有効。
ただし、家と学校はすでに土台があるので、実際の実装順としては以下が現実的。

- 家: 既存ステージの体験密度を上げる
- 学校: 既存イベントの意味付けを強める
- 第3エリア: 繁華街か駅前のどちらかに絞って追加する

つまり、新規に大量追加するのではなく、`既存2エリアを活かしつつ、対照的な外部エリアを1つ足す` 形がよい。


## 優先順位

### 優先1: ストーリーの外部ファイル化

`MainScene.gd` に会話がべた書きされたままだと、エリアやイベントを増やした時点で管理不能になる。
そのため、ゲームループ拡張の前に最低限ここを整理したい。

最低ライン:

- ダイアログ定義を外部JSONか辞書ファイルへ分離
- `MainScene.gd` 側は「読む」「分岐する」に責務を絞る

これは見た目の派手さはないが、今後の追加コストを大きく下げる基盤作業。

### 優先2: 1学期ループの縦切り

まずは1学期の中で以下が回る状態を目指す。

1. 今学期どこで過ごすかを選ぶ
2. エリア固有イベントが起きる
3. ストレスや注目が変動する
4. 身体測定で締める

この時点では卒業まで通せなくてもよい。
まず1学期で「今回は学校を選んでよかった」「次は外に行ってみたい」と思えることが重要。

### 優先3: ストレス表現の可視化

`ストレス` は数値だけでなく、見た目にも出したい。
レビュー案の `猫背` は相性がよい。

候補:

- 頭の角度が少し下がる
- 腰の角度が少し前に入る
- 待機姿勢だけ少し縮こまる

注意点:

- 当たり判定や自動屈みとは切り分ける
- まずは演出用の軽い姿勢変化として入れる

### 優先4: 表示の見やすさ改善

解像度が低く、せっかくの細かい描写が伝わりにくい問題がある。
これは十分解決の余地があるが、単に解像度を上げるだけではなく、`見せ方` の設計が必要。

候補:

- カメラズームの見直し
- 比較対象に近づいたときだけ見せる寄り演出
- UIで比較情報を補助する
- 線やシルエットが潰れない表示調整

ここは独立した調整テーマとして扱う。

### 優先5: 移動スケールの整合

歩幅と速度のズレは小さいが、体格シミュレーションの説得力を削る。
大きくなるほど一歩が伸びるなら、移動速度もある程度は伸びるべき。

この項目は軽微バグとして順次見直す。
